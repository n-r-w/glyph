# Ticket: PHS-12.2 - Standard TUI viewport navigation

Keep the complete transcript reachable through keyboard and mouse navigation while model and tool output continues to stream.

## Key definitions and abbreviations

- DEF-01: Transcript viewport. The terminal region showing a bounded rendered portion of the complete logical transcript.
- DEF-02: Follow mode. Viewport behavior that keeps the newest transcript content visible.
- DEF-03: Prompt marker. The start position of one rendered user message.

## Problem Statement

- PRB-01: Transcript content above the terminal height is not reachable. The standard TUI has no viewport position, follow mode, prompt navigation, search, scroll indicator, hyperlink activation, or transcript selection.

## Target Picture

- SOL-01: The user can reach, search, select, and copy every transcript block without stopping streaming output or losing the reading position after terminal resize.

## Scenarios

### SCN-01: Inspect earlier content during streaming

- Actor: standard TUI user.
- Pre-condition: DEP-01 is met.
- Trigger: the user scrolls upward while a model response continues to stream.
- Required behavior: streaming continues, the reading position remains anchored, and moving to transcript end resumes DEF-02.
- Example input and expected output: Input: scroll from the bottom to an earlier tool result, receive 100 model deltas, search for a prior prompt, and invoke bottom navigation. Expected output: the earlier tool result remains visible until navigation, search reaches off-screen content, and bottom navigation shows the newest response and follows later deltas.

## Scope

In scope:
- ISP-01: Transcript viewport requirements FRQ-11 through FRQ-20 and resize requirement FRQ-40 in [`standard-tui.md`](../standard-tui.md).

Out of scope:
- OSP-01: Editor history, completion, image paste, external editor, selectors, and extension-provided scrollable regions.

## Dependencies and Preconditions

- DEP-01: [PHS-12.1](12.1-standard-tui-rendering-layout.md) must meet all acceptance criteria.

## Requirements

### Goals

- GOL-01: Make every transcript block reachable while preserving deterministic follow, search, selection, and resize behavior.

### Functional Requirements

- FRQ-01: Enable DEF-02 only while DEF-01 is at the transcript bottom.
- FRQ-02: Keep incoming transcript updates without moving DEF-01 while follow mode is disabled.
- FRQ-03: Support movement by line, half page, page, transcript start, transcript end, preceding DEF-03, and following DEF-03.
- FRQ-04: Search the complete rendered transcript, highlight the active match, move to next and preceding matches, and close search without changing session content.
- FRQ-05: Route mouse wheel and trackpad scrolling to the transcript when no other scrollable TUI region owns the pointer location.
- FRQ-06: Display transcript scroll position whenever the complete transcript does not fit DEF-01.
- FRQ-07: Open rendered hyperlinks only after explicit click or key activation.
- FRQ-08: Support primary-button text selection, clipboard copy, and edge-triggered scrolling during selection.
- FRQ-09: Reflow after terminal resize while preserving the logical top block and intra-block position visible before resize.

### Non-Functional Requirements

- NFQ-01: Focused viewport tests must demonstrate RED and GREEN, followed by passing `task lint` and `task test`.
- NFQ-02: Keyboard navigation and search must remain available without mouse reporting or clipboard integration.
- NFQ-03: Viewport, search, and selection state must not change persisted session entries.

### Deliverables

- DLV-01: Transcript viewport, follow mode, scroll indicator, prompt navigation, and search.
- DLV-02: Mouse scrolling, hyperlink activation, transcript selection, and resize anchoring.
- DLV-03: Process-level streaming and resize fixture with a transcript longer than multiple terminal heights.

### Acceptance Criteria

- ACC-01: A transcript of 300 rendered lines can navigate to its first and last lines through keyboard actions.
- ACC-02: After scrolling upward, 100 incoming deltas do not change the logical top block or intra-block offset.
- ACC-03: Transcript-end navigation enables follow mode and later deltas remain visible.
- ACC-04: Search finds matches above and below the visible region and cycles in both directions.
- ACC-05: Resizing at a wrapped block preserves that block and its visible source position.
- ACC-06: Mouse and keyboard scrolling reach equivalent transcript positions.
- ACC-07: Hyperlinks never open from rendering or pointer movement without explicit activation.
- ACC-08: Drag selection copies the selected source text and can extend beyond one viewport height.

## Overengineering and Overspecification Considerations

This ticket provides one Glyph viewport and does not copy Pi regular and fullscreen modes. Mouse behavior supplements the complete keyboard path.

## Constraints and Risks

- RSK-01: Raw row offsets become invalid after width changes. Anchor the viewport to logical block identity and source-relative position.
- RSK-02: Search over rendered rows can return stale geometry after streaming updates. Keep match source positions and recalculate visible geometry from the active render width.
- RSK-03: Mouse reporting can obstruct terminal-native selection. Terminal modes must be disabled on suspension and termination by PHS-12.3.
