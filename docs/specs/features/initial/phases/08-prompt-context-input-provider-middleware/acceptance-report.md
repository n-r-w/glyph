## Verification limits

1. **Missing or indirect RED.** UNT-01 has no complete RED history: the initial missing-behavior records are recovered from saved transcripts, and some RED pairs are unavailable ([UNT-01 limits](unt-01-evidence.md#verification-limits-and-handoff)). UNT-02 tests of the runtime generation and of the C2 and C3 callers have no RED ([UNT-02](unt-02-evidence.md#c2-and-c3-public-caller-replay-and-cancellation-tests)). UNT-03 lists tests written after their code ([UNT-03](unt-03-evidence.md#part-2-tests-without-recorded-red)). UNT-04 took several REDs by disabling one mechanism for one run ([UNT-04](unt-04-evidence.md#focused-red-and-green)).
2. **Unit level only.** `AddedHistory`, finalized length-limit results, kept accounting and provider identity, and cancellation without finalized-message handlers are checked only in unit tests ([UNT-04](unt-04-evidence.md#evidence-limits)). Context runtime loss and cancellation have no public test.
3. **Platform skips.** `TestStandardTUIHostSmoke` runs on Darwin arm64 only, so Linux runs record no standard-TUI result. `TestRunWithPathsHeadlessPersistenceFailurePreservesContext` and `TestResumeRecoveryPersistenceFailureProcessPath` skip on this platform ([UNT-03](unt-03-evidence.md#checks), [UNT-04](unt-04-evidence.md#checks-after-round-3)).
4. **Streamed text before finalization.** Programmatic and UI clients receive streamed content and tool-call events before finalization, so those events carry provisional values. `MESSAGE_END`, the tool events that complete a call, the session and later requests carry the final value ([D8-18](decisions.md#d8-18-user-and-configured-model-finalization-and-the-finalized-message-reference), [finalized-message guide](../../../../../guidelines/finalized-message-middleware.md#when-handlers-run)). Finalized-message handlers cannot change text that a client already received.
5. **No production extension provider.** PHS-12 delivers extension-defined providers. The provider-independence evidence uses a generated raw-provider substitute.
6. **Local provider fixtures.** Every provider in the tests is a local HTTP fixture. No live provider, credential or incident is claimed.
7. **Direct-import boundary check.** The check covers direct imports. `host/internal/usecase/agent/run` reaches protobuf and gRPC packages transitively through its import of `host/internal/usecase/host/programmatic`, which imports the Programmatic controller. This edge exists at the commit before PHS-08 (`b332e05`) and PHS-08 adds none.
8. **Lint without the integration tag.** The unfiltered no-tag lint of the UNT-01 packages reports findings outside changed lines ([UNT-01](unt-01-evidence.md#additional-no-tag-lint-finding)); the project lint task passes.
9. **Overflow-recovery persistence failure.** No public fixture injects a persistence failure into an overflow-recovery commit that also has a finalization failure. The category of that combination is checked at unit level only ([UNT-04 round 3](unt-04-evidence.md#c12-every-category-lookup-of-the-accepted-run-classifiers-reads-current-causes)).
10. **Secret collection without wire callbacks.** Successful-response secret tests install wire callbacks. The no-callback success collector path is checked by source inspection only, and no generic compatible rejection-body capture exists ([UNT-01](unt-01-evidence.md#review-boundary-and-limits)).
11. **Retained outside-task finding.** `Runtime.context` in `host/internal/infra/plugins/extension/runtime/runtime.go` stores a `context.Context`. UNT-01 reported it without investigation or change ([UNT-01](unt-01-evidence.md#wording-reconciliation-and-limits)).
12. **No user acceptance yet.** The last full project checks ran on the code of UNT-04 (`c2cf46a`). UNT-05 changes documentation only, so the code of the phase head is the code those checks covered. Final verification and user acceptance remain open.
